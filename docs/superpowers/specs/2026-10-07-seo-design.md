# SEO

## Problem

The public half of the platform — the landing page, storefronts and product
pages — is barely legible to search engines or to anything that unfurls a
shared link:

- The root layout still carries `create-next-app`'s metadata ("Create Next
  App" / "Generated by create next app"). There is no `metadataBase` and no
  title template, so every page without its own description inherits the
  placeholder and titles like "Explore" carry no brand.
- No `robots.ts`, no `sitemap.ts`. Nothing tells a crawler which pages matter
  or which are private.
- Every product and storefront answers on several URLs. The product page
  ignores its `[slug]` segment, so `/@gabi/12/anything` renders the same page,
  and renaming a product re-slugs it (`updateUserProduct`), splitting its
  ranking across the old and new URL. `parseHandleSegment` strips the `@`, so
  `/gabi` and `/@gabi` are both the storefront. No page declares a canonical.
- No Open Graph or Twitter data anywhere: a shared product link shows no
  image, name or price, though products have images and sellers have an
  avatar and bio.
- No structured data, so no price or availability in search results.
- The product meta description is the raw full description; the storefront's
  is fixed boilerplate even when the seller has a bio.

## Goal

Make storefronts and product pages indexable under exactly one URL each, with
correct titles, descriptions, generated share cards and `Product` structured
data, and keep every private page out of the index — using Next's own metadata
APIs and file conventions throughout.

## Decisions

| Question | Choice | Why |
| --- | --- | --- |
| `/explore` | Stays login-gated, noindex; TODO entry | Making it public is a product change (it lives in `DashboardShell`), not metadata. |
| Non-canonical URL | `permanentRedirect()` (308) plus `alternates.canonical` | Old links survive a rename and ranking moves to the new URL; a 404 on slug mismatch would break every link the seller has shared. |
| Share images | Generated `opengraph-image.tsx` cards | Uniform 1200×630 cards carrying name, price and handle; no product or seller is left without one. |
| Private pages | `robots: { index: false }` metadata, not robots.txt `Disallow` | A disallowed URL can still be indexed from inbound links; noindex is only seen by a crawler allowed to fetch the page. |
| Structured data | `Product` JSON-LD only | It is the only type that earns a rich result here. |

Rejected: a canonical tag without a redirect (variants still render and get
shared); reusing raw `openGraph.images` (square covers cropped, no price, and
nothing at all for a product without images or a seller without an avatar).

## 1. Metadata foundation

**`lib/site.ts`** (new, environment-agnostic): `SITE_NAME = 'Creator
Commerce'` and `SITE_DESCRIPTION`. The one source for the root metadata, the
OG cards and the JSON-LD.

**`app/layout.tsx`** replaces the placeholder with:

- `metadataBase: new URL(appUrl)` (`lib/server/app-url.ts`). Every relative
  canonical, OG image url and alternate then resolves against the deployment's
  own host — production domain, preview alias or localhost — with no host
  written anywhere.
- `title: { default: 'Creator Commerce — Sell your digital products',
  template: '%s · Creator Commerce' }`.
- `description: SITE_DESCRIPTION`, `applicationName: SITE_NAME`,
  `openGraph: { siteName: SITE_NAME, type: 'website', locale: 'en_US' }`,
  `twitter: { card: 'summary_large_image' }`.

The landing page (`app/(public)/page.tsx`) drops its own `title` and inherits
the default.

**`toMetaDescription(text: string, max = 160)`** in `lib/utils.ts`: collapses
runs of whitespace (descriptions are `whitespace-pre-line` multi-paragraph
text), and if still over `max`, cuts at the last word boundary before it and
appends `…`. The product page passes the description through it; the
storefront uses the seller's `bio` through it when present, and today's
boilerplate otherwise. `getUserByHandle` (`lib/server/dal/users.ts`) already
selects `image`; it gains `bio`, and `PublicUser` with it. A bio is public
text the seller wrote for their storefront, so it belongs in that deliberately
narrow type.

## 2. Crawl control

**`isProductionDeployment`** exported from `lib/server/app-url.ts`:
`process.env.VERCEL_ENV === 'production'`.

**`app/robots.ts`**:

- Production: `allow: '/'`, `disallow: ['/api/', '/dev/', '/checkout/',
  '/oauth/']`, `sitemap: \`${appUrl}/sitemap.xml\``.
- Anything else (preview, local): `disallow: '/'`. Vercel already sends
  `X-Robots-Tag: noindex` on preview hosts; this is the same rule stated by
  the app itself, so it holds on any host.

**`robots: { index: false }`** in the metadata of these layouts:
`app/(master)/layout.tsx` (dashboard, products, sales, purchases, downloads,
settings, wishlist, explore, help), `app/(auth)/layout.tsx`,
`app/cart/layout.tsx`, `app/checkout/layout.tsx`. Each is a static `metadata`
export; none of them otherwise exports metadata today.

The product page keeps its existing `robots: { index: false }` for drafts.

## 3. Canonical URLs

**`lib/paths.ts`** (new, environment-agnostic):

```ts
export function storefrontPath(handle: string): string // `/@${handle}`
export function productPath(handle: string, id: number, slug: string): string
```

`productPath` substitutes `'product'` when `slug` is empty: `slugify` returns
`''` for a name with no ASCII letters or digits ("★★★"), and the `[slug]`
segment cannot be empty, so such a product's link 404s today.

`storefrontLink` and `productPageLink` are deleted from
`lib/server/tools/shared.ts`, and their callers (`tools/products.ts`,
`tools/account.ts`, `tools/marketplace.ts`, `tools/purchases.ts`) import
`storefrontPath` / `productPath` instead — `lib/paths.ts` imports nothing, so
the tools' import rule (no `ai`, `next/*`, Sentry or `request/`) still holds.
`productEditLink` stays where it is. The inline builders in
`components/product-card.tsx` and `app/cart/page.tsx` switch to
`productPath`. One builder for every product url in the app.

**Storefront page** (`app/(public)/[handle]/page.tsx`): after resolving the
seller, if `decodeURIComponent(handle) !== \`@${user.handle}\``, call
`permanentRedirect(storefrontPath(user.handle))`. Comparing the decoded
segment is what keeps `/%40gabi` from redirecting to itself forever.
`generateMetadata` sets `alternates: { canonical: storefrontPath(user.handle) }`.

**Product page** (`app/(public)/[handle]/[id]/[slug]/page.tsx`): the same
handle check, and `slug !== canonicalSlug` → `permanentRedirect(productPath(...))`,
where the canonical url is `productPath(user.handle, product.id,
product.slug)` and the comparison is against the path segment that url
produces (so the empty-slug fallback is compared like any other slug).
`generateMetadata` sets `alternates.canonical` to that same path.

`getStorefrontProduct` (`lib/server/dal/products.ts`) selects `slug` again and
`StorefrontProductDetail` gains it; its comment ("No slug: that page … never
needs its own") is rewritten to say the page needs it to redirect to the
canonical url.

The redirect runs in the page, not the layout: the layout knows the handle but
not the rest of the path.

## 4. Open Graph cards

All three are `opengraph-image.tsx` files returning `ImageResponse` at
1200×630, `contentType = 'image/png'`. Twitter falls back to `og:image` under
`summary_large_image`, so no `twitter-image` files.

**`lib/server/og/`** (new, server-only) holds what the three share:

- The frame: background, padding, a small `SITE_NAME` wordmark, and a slot
  for the card's content.
- Colours from `lib/email-theme.generated.ts`. Satori cannot parse `oklch()`
  any more than an email client can, and that file is already the palette in
  hex — no second copy.
- Fonts: Roboto (headings) and Nunito Sans (body) TTFs committed under
  `assets/fonts/`, read with `readFile(join(process.cwd(), 'assets/fonts/…'))`
  as the Next docs show. `next/font` exposes nothing Satori can load.
- `loadCover(url)`: fetches a product image and returns it only if its
  `content-type` is `image/png` or `image/jpeg`, else `null`. Satori's decoding
  of WebP/AVIF is not something to rely on; an unsupported cover renders the
  no-cover variant rather than a broken card. Verify this against a real
  UploadThing upload during implementation.

**Cards:**

- `app/(public)/opengraph-image.tsx` — landing. Wordmark, the hero line
  ("Sell your digital products in minutes"), `SITE_DESCRIPTION`. Reads no data;
  prerendered at build.
- `app/(public)/[handle]/opengraph-image.tsx` — storefront. Avatar if the
  seller has one, name, `@handle`, bio (through `toMetaDescription`), and the
  count of published products. Inherited by nested routes unless overridden.
- `app/(public)/[handle]/[id]/[slug]/opengraph-image.tsx` — product. Cover on
  the left (or a brand-coloured panel with a file icon when `loadCover` returns
  `null` or there are no images), name, `formatPrice(priceInCents)` and
  `@handle` on the right.

**Rules for the two dynamic cards:**

- They read **published, non-deleted rows only, and never the session**. A
  card route is a separate request that the owner-only draft logic of the page
  does not cover; reading drafts there would render a draft's name and price
  for anyone who guesses the url. A missing, draft or deleted row calls
  `notFound()`. A draft's page still points `og:image` at that 404 — harmless,
  since only its owner can see the page and it is noindex.
- They do not check the handle/slug segments beyond resolving the row: the
  page already redirects to the canonical url, and the card url hangs off it.
- `export const revalidate = 3600`. Social platforms cache cards for days
  anyway; an hour-stale price on a card is acceptable.
- Alt text through `generateImageMetadata`, returning one image with
  `alt: product.name` / `alt: \`${user.name} on Creator Commerce\``, so it is
  not one fixed string. That puts the card at
  `…/opengraph-image/<id>`; Next emits the url, nothing hardcodes it.

The DAL reads they need: the product card can use `getStorefrontProduct(id,
ownerId, { includeDrafts: false })` after `getUserByHandle`; the storefront
card takes `published` from `getSellerProductCounts(user.id)`, which already
excludes soft-deleted rows.

## 5. Structured data

**`lib/seo/json-ld.ts`** (new, environment-agnostic), two pure functions:

- `productJsonLd({ product, seller, url, imageUrls })` returns a schema.org
  `Product`: `name`, `description`, `image` (absolute urls), `url` (absolute
  canonical), and `offers` — an `Offer` with `price` as a decimal string
  (`(priceInCents / 100).toFixed(2)`), `priceCurrency: APP_CURRENCY`,
  `availability: 'https://schema.org/InStock'`, `url`, and `seller: { '@type':
  'Person', name, url: <absolute storefront url> }`.
- `serializeJsonLd(data)`: `JSON.stringify(data).replace(/</g, '\\u003c')`.
  Name and description are seller-written; without the escape a `</script>` in
  a description closes the tag and the rest runs as HTML.

The product page renders `<script type="application/ld+json"
dangerouslySetInnerHTML={{ __html: serializeJsonLd(...) }} />` for published
products only. Absolute urls come from `appUrl`; the page is a server
component, so importing it is fine.

No `schema-dts` dependency: one type, hand-written, is not worth an install.

## 6. Sitemap

**`listSitemapEntries()`** in `lib/server/dal/products.ts`: one query, every
published non-deleted product joined to its seller's `handle`, selecting
`id`, `slug`, `updatedAt`, `images` and `handle`.

**`app/sitemap.ts`**, `export const revalidate = 3600`, builds from that:

- `appUrl` (landing).
- One entry per distinct seller handle — storefronts with at least one
  published product — with `lastModified` the newest `updatedAt` among their
  products. Empty storefronts are left out as thin pages.
- One entry per product: `productPath(...)` against `appUrl`, `lastModified:
  updatedAt`, `images` (absolute urls as stored).

A single sitemap holds 50,000 urls; sharding with `generateSitemaps` waits
until that is close (TODO).

## 8. Testing

**Vitest:**

- `toMetaDescription`: short text unchanged; whitespace collapsed; long text
  cut at a word boundary with `…`, never over `max`.
- `productPath`: normal slug; empty slug → `product`.
- `productJsonLd` / `serializeJsonLd`: price `2900` → `"29.00"` with
  `RON`; a description containing `</script>` serializes with no literal `<`.

**Playwright** (seeded through `createSeedScope`; assert only on the test's own
tagged rows):

- `/<handle>` (no `@`) and `/@<handle>/<id>/wrong-slug` each answer 308 to
  the canonical url (`request.get(..., { maxRedirects: 0 })`).
- The product page has `<link rel="canonical">` at the canonical url, an
  `og:image` meta, and a JSON-LD script whose `name` is the product's.
- `/robots.txt` answers 200 (its content differs by environment, so only
  that).
- `/sitemap.xml` contains the seeded published product's url and not a seeded
  draft's.
- The product card url (read from the page's `og:image`) answers 200
  `image/png`; the same route for a seeded draft answers 404.
